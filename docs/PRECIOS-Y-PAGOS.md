## 1. Resumen ejecutivo

1. En OnlyFans el precio mediano de suscripción es **USD 10/mes** (promedio USD 13.71); el 73% de las páginas de pago cobran entre USD 5 y USD 15. La suscripción es el gancho, no el negocio: **72.8% de los ingresos de OnlyFans en 2025 vino de mensajes, PPV y propinas**, no de suscripciones.
2. Para Guatemala conviene un precio de entrada bajo en GTQ (**Q99–Q149**) y monetizar en el chat, PPV y llamadas. Para audiencia internacional, **USD 9.99–19.99**.
3. La comisión estándar del mercado es **20% plataforma / 80% creadora**. Pero con una pasarela de alto riesgo que cobra 13–15%, un 20% deja muy poco margen. Recomiendo **25% en pagos con tarjeta adulta** y **20% en cripto/transferencia**, o un 20% + costo de procesamiento visible.
4. Recurrente **no sirve para tarjeta de contenido adulto**. Solo permite transferencia/PayPal para ese giro. Sí puede servir para la vertical de **masajes, spa, belleza, fotografía y eventos** si aprueban la cuenta.
5. No se puede poner un “recargo por tarjeta” en Guatemala: las reglas de Visa no lo permiten en LAC y Mastercard tampoco lo permite como recargo. Se resuelve con **precio todo incluido** o **descuento por transferencia/cripto**, no con recargo.

### Qué recomiendo para arrancar

**Fase 1 (mes 1–2):**
- **Servicios profesionales:** Recurrente (tarjeta + ACH) y transferencia. Comisión 18%.
- **Contenido adulto:** cripto (NOWPayments) + transferencia manual para fans locales; wallet con recargas.
- **No** intentes meter adulto por Recurrente “disimulado”. El MCC y la revisión de contenido lo detectan; el riesgo es perder la cuenta y los fondos.

**Fase 2 (mes 3–6):**
- Solicitar **CCBill + Segpay** en paralelo (dos opciones reduce dependencia).
- Comparar cotización escrita: porcentaje, registro anual, reserva, chargeback, reintentos y payout.
- Añadir tarjeta cuando la tasa de chargeback esté bajo 1%.

**Fase 3 (mes 6+):**
- Negociar volumen; añadir adquirente local para servicios; evaluar Pix/ACH LatAm si expandes.

### Sobre el “recargo”

- **Visa Core Rules 1.5.5.2**: el comercio no puede añadir un monto sobre el precio normal, salvo que la ley lo permita. Las excepciones son EE. UU., Canadá, Nueva Zelanda y algunos casos; **no hay excepción para Guatemala/LAC**.
- **Mastercard 5.12.2**: prohíbe recargar al tarjetahabiente; permite **descuento por efectivo**.
- Por eso: **no pongas “+5% por tarjeta”**. En su lugar:
  - Precio único con todo incluido (recomendado).
  - “Paga por transferencia y recibe 5% de descuento” (descuento, no recargo).
  - Mínimo de producto (ej. recarga mínima Q50) para que el Q2 fijo no se coma el margen.
- Tampoco puedes poner mínimo por tarjeta; sí puedes definir un precio mínimo de producto.

### Impuestos y facturación

- **IVA 12%** sobre servicios digitales; define si tus precios son “IVA incluido” o “+ IVA”.
- **FEL/SAT** para cada venta y para la liquidación a creadoras/profesionales.
- **ISR y retenciones** según el régimen de cada prestadora; valida con contador.
- guarda **comprobantes de payout** y contratos de intermediación.

## 6. Firebase Auth + Gmail: cómo lo haría

- **Firebase Authentication** con proveedor **Google** y email/contraseña. Free hasta **50,000 MAU**; arriba de eso USD 0.0055/MAU (2026).
- El cliente obtiene el **ID token**; el backend (NestJS/Next) lo verifica con Firebase Admin SDK y crea/actualiza el usuario en PostgreSQL.
- **Custom claims** para roles: `fan`, `creator`, `provider`, `moderator`, `admin`. Nunca confíes en el rol que manda el cliente.
- **Age gate**: Google no garantiza edad. Pide fecha de nacimiento y, para creadoras/profesionales, KYC con documento + selfie antes de publicar o cobrar.
- **App Check** para evitar abuso de la API; **2FA** para admin y creadoras.
- **No uses Firebase Storage** para video adulto: costoso y con políticas restrictivas. Usa R2/Bunny + URLs firmadas; Firebase solo para auth y metadata no sensible.
- **Account linking** para que un usuario pueda entrar con Google o email sin duplicar cuenta.
- **Emulador** local para desarrollo; variables en Coolify.

Flujo:
```
Google/Email → Firebase Auth → ID token → API /auth/session
→ verifica token → upsert user → emite cookie httpOnly + refresh
→ chequea age gate → si creator, exige KYC → habilita panel
```

## 7. Protección anti-descarga: qué es realista

| Capa | Qué hace | Límite |
|---|---|---|
| URL firmada (5–15 min) | Evita compartir enlaces | Se puede copiar mientras está activo |
| HLS segmentado | Dificulta descarga directa | Herramientas pueden bajar segmentos |
| DRM Widevine/FairPlay | Cifra el video en el dispositivo | Costoso y complejo; no disponible en todos los navegadores |
| Marca de agua por usuario | Identifica filtraciones | Disuade, no impide |
| Límite de dispositivos/sesiones | Reduce cuentas compartidas | Afecta usuarios legítimos |
| Detección de duplicados | Encuentra contenido re-subido | Requiere fingerprinter/hash |
| DMCA/takedown | Retira copias | Depende de la plataforma externa |

**Mensaje honesto:** no existe “anti-descarga 100%”. Lo que sí puedes prometer es **streaming protegido, marca de agua, URLs firmadas, registro de accesos y takedown rápido**. Para video premium, DRM es la única barrera fuerte; para fotos, watermark + signed URLs + monitoreo.

## 8. PayPal: respuesta directa

**No sirve para suscripciones de contenido adulto.**

- La política de PayPal prohíbe “certain sexually oriented materials or services” y trata el **contenido para adultos digital** (videos, fotos descargables, suscripciones a sitios) como categoría restringida o prohibida. No es solo “pedir aprobación”: el contenido explícito digital normalmente queda fuera.
- Una **cuenta personal** no es para cobrar un negocio. Si la usas para vender, violas los términos y te exponen a limitación, congelamiento y cierre.
- **Tu nombre sí aparece** en una cuenta personal. En una cuenta Business aparece el nombre del negocio, pero el negocio debe estar aprobado y el giro declarado; no puedes “esconder” el adulto.
- Si PayPal detecta el giro, puede **retener el saldo hasta 180 días** y cerrar la cuenta. Los chargebacks de contenido adulto son altos.
- Las suscripciones recurrentes no son una función pensada para cuentas personales; requieren Business y aprobación.

**Veredicto:** no uses PayPal para el lado adulto. Para **servicios profesionales** (masajes no sexuales, spa, fotografía) podrías usar una cuenta Business si PayPal aprueba el giro, pero Recurrente es más local y transparente. No arriesgues la cuenta personal.

## 9. Cómo cobra la plataforma y cómo reparte el 80/20

El modelo práctico:

1. **AMY es el comercio** ante la pasarela (merchant of record). El fan paga a AMY.
2. La pasarela liquida a AMY, no a cada creadora. No existe “split” automático en la mayoría de PSP de alto riesgo.
3. AMY registra en un **ledger de doble entrada**:
   - venta bruta,
   - comisión AMY,
   - costo de pasarela,
   - saldo de la creadora (pendiente → disponible),
   - reserva para chargebacks,
   - payout.
4. La creadora solicita retiro; AMY paga por transferencia bancaria o USDT, con comprobante y factura.
5. Si hay chargeback, se descuenta del saldo pendiente o se compensa contra ventas futuras.

**Comisión recomendada:** 25% en tarjeta adulta (la plataforma absorbe el PSP), 20% en cripto/transferencia, 18% en servicios. La creadora recibe el 75/80/82% del bruto, según el método.

Ejemplo Q150 con tarjeta y 25%:

| Concepto | Monto |
|---|---|
| Fan paga | Q150 |
| Creadora (75%) | Q112.50 |
| AMY (25%) | Q37.50 |
| PSP 15% + Q2 | −Q24.50 |
| **Margen AMY** | **Q13.00** |

Con 20% AMY solo se queda Q5.50 antes de costos. Por eso el 25% en tarjeta no es codicia: es supervivencia.

**Payouts:** mínimo Q200, viernes, retención del 10% durante 90 días para cubrir disputas (o según la reserva del PSP). La creadora debe estar verificada y emitir factura.

## 10. R2 + Cloudflare + Firebase: arquitectura recomendada

- **R2:** guarda originales, HLS y miniaturas en un bucket **privado**. Nunca público.
- **Entrega:** URLs firmadas de corta duración. Para video adulto, usa **Bunny CDN** como capa de entrega (permite contenido adulto legal y está pensado para video); R2 queda como origen privado. Cloudflare puede servir HTML, API y miniaturas.
- **Cloudflare R2/Stream para video adulto público:** revisa el AUP y pide confirmación por escrito. Hay operadores que reportan restricciones para servir video adulto desde R2/Stream; la práctica segura es R2 privado + CDN especializado.
- **Firebase:** solo **Authentication** (Google/Gmail). No uses Firebase Storage para contenido adulto. Firestore es opcional para metadata; PostgreSQL es la fuente de verdad.
- **HLS:** 3 calidades, segmentos de 4–6 s, `signed cookies` o tokens por sesión.
- **Marca de agua:** ID de usuario + timestamp, visible y invisible.
- **DRM:** opcional (Widevine/FairPlay) cuando haya volumen; no es requisito para arrancar.
- **Anti-descarga:** no existe 100%; hay disuasión, trazabilidad y takedown.
